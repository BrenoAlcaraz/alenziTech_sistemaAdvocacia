🟢 O que é
Esta tela do protótipo sempre mostra o Painel como o mestre vê — completo, com financeiro, Análise de dados e Painel do gestor. Só que o Painel de um usuário comum (Administrador, Ilimitado ou Financeiro) muda de acordo com a Permissão "Painel" (Somente os seus / Todos) configurada em Configurações → Permissões: "Todos" mostra o painel completo do escritório, igual o mestre vê; "Somente os seus" mostra uma versão com os números limitados aos processos/clientes que o usuário tem permissão de ver — a mesma lógica derivada de Processos que já vale nos outros módulos. O dono do escritório decide isso por papel, e pode ajustar individualmente na aba Individual se quiser dar a alguém específico uma visão diferente da regra geral do papel.
🔴 Como construir
Consulte permissoes_papel.painel.sub_opcao (ou o override em permissoes_usuario, se existir) pro usuário logado. Se 'todos': renderize o painel completo, igual está aqui no protótipo. Se 'somente_seus': filtre os dados exibidos pelos processos/clientes que o usuário pode ver (mesmo filtro de equipe_processos + usuario_processos já usado em Processos) — o detalhamento exato de como cada card se comporta nessa versão está descrito logo abaixo, junto com os cards de resumo. O Painel em si não tem lógica própria de permissão — só lê a decisão já configurada em Configurações. No backend, a própria API que devolve esses dados deve checar essa mesma permissão antes de responder — nunca confie só em esconder no front.

Este protótipo sempre mostra a visão completa (perfil mestre). Veja abaixo como cada card se comporta para um usuário comum, conforme a Permissão/Habilitação configurada para ele.
🟢 O que é (visão do mestre, mostrada aqui)
Painel de resumo do escritório em números simples: quantos clientes o escritório atende, quantos processos estão em andamento, quantas tarefas o advogado logado ainda precisa fazer, quantos compromissos tem marcados em breve, a situação financeira (A receber/A pagar/Diferença) e quantos usuários estão ativos. O mestre sempre vê tudo isso completo, sem filtro nenhum.
🔴 Como um usuário comum vê cada card — regra por módulo
Importante antes de tudo: a Permissão de um módulo tem dois níveis — o módulo pode estar habilitado: false (desligado por completo) ou habilitado: true com uma sub_opcao ('somente_seus'/'todos'). Quando está desligado, o card correspondente não aparece de forma nenhuma — não mostra "0", simplesmente não é renderizado, como se aquela informação não existisse pra esse usuário. Só quando o módulo está ligado é que a sub_opção decide se conta tudo ou só o que ele está habilitado.

Clientes ativos: some se permissoes_papel.clientes.habilitado === false. Se ligado: 'todos' conta o escritório inteiro; 'somente_seus' conta só os clientes vinculados a processos em que ele está habilitado (cliente nunca é habilitação direta, é sempre consequência de acesso a processo).

Processos ativos: some se permissoes_papel.processos.habilitado === false. Se ligado: mesma lógica de 'todos'/'somente_seus' aplicada aos processos (via equipe ou individualmente).

Tarefas pendentes: some se permissoes_papel.tarefas.habilitado === false. Se ligado: 'todos' conta as tarefas pendentes de qualquer usuário; 'somente_seus' conta só as dele mesmo.

Compromissos próximos: some se permissoes_papel.agenda.habilitado === false. Mesma lógica de sub_opção aplicada à Agenda quando ligado.

Card financeiro: some se permissoes_papel.financeiro.habilitado === false. Se ligado com sub_opcao === 'acesso_dados', mostra os valores normais (A receber/A pagar/Diferença); se 'apenas_solicitacoes', mostra "Solicitações de pagamento requeridas: N" em vez de valores financeiros.

Usuários ativos: não depende de Permissão de módulo — aparece pra qualquer usuário com a habilitação habilitacoes_papel.gerir.criar_novo_usuario === true.

Navegação: cada card visível é um link/botão clicável que redireciona para o módulo correspondente: "Clientes ativos" → módulo Clientes; "Processos ativos" → módulo Processo; "Tarefas pendentes" → módulo Tarefas; "Compromissos próximos" → módulo Agenda; o card financeiro → módulo Financeiro (na aba certa: Pagamentos se tem acesso a dados, Solicitações se só tem solicitações); "Usuários ativos" → módulo Configurações, tela de usuários — sempre já filtrado pelo mesmo escopo que o card estava mostrando. Esse padrão se repete em praticamente todo o Painel — vale criar um componente reutilizável (ex: <CardClicavel rota="/clientes">) em vez de reescrever a navegação em cada card.

🟢 O que é
Mostra quais processos tiveram algum andamento registrado recentemente (nas últimas 24 horas ou nos últimos 7 dias). Andamento é qualquer evento novo no processo — uma decisão do juiz, uma petição protocolada, uma citação confirmada. Esse painel ajuda o advogado a saber rapidamente "o que mudou" no escritório sem precisar abrir processo por processo pra checar.
🔴 Como construir
Já existe a tabela de andamentos (a timeline que fizemos no módulo Processo). Filtre: andamentos.data >= now() - 24h para o primeiro grupo, e andamentos.data >= now() - 7 dias para o segundo. Agrupe por processo (DISTINCT) pra não contar duas vezes um processo que teve dois andamentos no período.

Depende de Processos estar ligado: este painel inteiro só renderiza se permissoes_papel.processos.habilitado === true — se o módulo Processos estiver desligado pra esse papel (ex: o Financeiro, que normalmente não precisa desse dado), o painel de Movimentação processual não aparece de forma nenhuma, junto com Paralisados/Prazos a vencer/Intimações (mesma regra explicada nos cards deles).

Navegação: ao clicar no mini-card (ex: "24h"), abra abaixo dele a seção com a lista dos processos daquele grupo (nome/número/motivo, pegando o andamento mais recente de cada um como "motivo"). Cada processo da lista precisa ser clicável — ao clicar, redirecione o usuário direto para o módulo Processo, já carregando a página daquele processo específico (rota tipo /processos/:id).

🟢 O que é
É o oposto da movimentação: mostra os processos "parados" — sem nenhum andamento registrado há mais de 1, 3 ou 6 meses. Um processo parado pode significar um prazo perdido, um processo esquecido, ou simplesmente que está aguardando decisão do juiz — mas o escritório precisa saber disso pra não deixar nada passar despercebido.
🔴 Como construir
Para cada processo, calcule hoje - MAX(andamentos.data) (a data do último andamento). Se essa diferença for maior que 30 dias, entra no grupo "+1 mês"; maior que 90, "+3 meses"; maior que 180, "+6 meses" — a contagem é cumulativa (um processo de 6 meses parado também conta nos outros dois grupos, é a forma mais simples e mais útil de mostrar). Processos arquivados/encerrados não devem entrar nessa contagem.

Depende de Processos estar ligado: mesma regra do painel de Movimentação — some junto se permissoes_papel.processos.habilitado === false.

Navegação: mesmo padrão dos demais painéis clicáveis — ao clicar no mini-card, mostre a lista de processos daquele grupo; ao clicar num processo da lista, redirecione para o módulo Processo na página daquele processo específico (/processos/:id).

🟢 O que é
Mostra os processos com prazo processual vencendo em breve — hoje, amanhã, em até 3 dias ou em até 5 dias. Prazo processual é uma data-limite que a lei ou o juiz determina para o advogado fazer alguma coisa (responder, recorrer, pagar uma custa, etc.). Perder um prazo pode prejudicar seriamente o cliente e até gerar responsabilidade para o advogado — por isso este é um dos painéis mais importantes de todo o sistema.
🔴 Como construir
Puxe da tabela de prazos (mesma da aba Prazos do módulo Processo) todos com status != 'cumprido' e calcule prazo.data - hoje. Diferença == 0 → "hoje"; == 1 → "amanhã"; entre 0 e 3 → "até 3 dias"; entre 0 e 5 → "até 5 dias" (contagem cumulativa, igual ao painel de paralisados). Por ser crítico, vale considerar no futuro notificação por push/e-mail além de só mostrar aqui no painel.

Depende de Processos estar ligado: mesma regra dos painéis anteriores — some junto se permissoes_papel.processos.habilitado === false.

Navegação: mesmo padrão — clicar no mini-card lista os processos daquele prazo; clicar num processo da lista leva direto para a página dele no módulo Processo.

O cadastro do e-mail e toda a lógica de identificar intimações já foi explicada no módulo Configurações. Aqui no Painel, essa aba apenas replica o resultado: mostra as intimações já identificadas que ainda exigem alguma manifestação nos próximos dias, pra o advogado ver isso de relance junto com o resto do resumo do escritório, sem precisar abrir o Configurações pra checar.

Faz sentido na prática: o exemplo mais comum de papel sem acesso a Processos é o Financeiro puro (alguém que só cuida do caixa do escritório) — essa pessoa não precisa saber quais processos estão parados, com prazo vencendo, ou com intimação pendente.

🟢 Quando esta aba aparece, e como filtrar
Análise de dados é toda derivada de Processos — então, igual os outros painéis que dependem de processo, ela só aparece se o módulo Processos estiver ligado pra esse usuário (permissoes_papel.processos.habilitado). Se estiver desligado, a aba nem aparece. Se estiver ligado com 'somente_seus', os dados já vêm naturalmente restritos aos processos em que ele está habilitado — sem escolha. Se estiver com 'todos', ele ganha um controle extra pra decidir, pra cada consulta, se quer ver os dados de todo o escritório ou só os processos dele mesmo — porque mesmo tendo acesso a tudo, às vezes ele quer só a própria carteira. Além disso, cada uma das análises abaixo (natureza, localidade, status, patrocínio) pode ser filtrada por Cliente, Equipe e — só pra quem está no escopo "Todos" — por Usuário, pra fatiar os dados exatamente como precisar (ex: "desse cliente específico, quantos processos são imobiliários e onde estão tramitando").
🔴 Como construir
A aba inteira só renderiza se permissoes_papel.processos.habilitado === true. Dentro dela, se sub_opcao === 'todos', mostre o seletor de escopo (Todos do escritório / Somente os meus) — ele é só um filtro adicional de WHERE responsavel_id = usuario.id quando "Somente os meus" está selecionado; se sub_opcao === 'somente_seus', aplique esse filtro sempre, sem mostrar o seletor (não tem o que escolher). Os filtros de Cliente/Equipe/Usuário são WHERE adicionais sobre a mesma base de processos (cliente_id = X, processo IN (SELECT processo_id FROM equipe_processos WHERE equipe_id = Y), responsavel_id = Z) — o filtro por Usuário só deve aparecer/funcionar quando o escopo estiver em "Todos" (não faz sentido filtrar por outro usuário se você já só vê os seus). Todas as 4 análises abaixo (natureza/localidade/status/patrocínio) devem reagir aos mesmos filtros ao mesmo tempo — um único estado de filtro compartilhado, recalculando as 4 de uma vez a cada mudança.

🟢 O que é
Mostra como os processos do escritório se distribuem por área do direito (natureza) e por onde estão tramitando. Localidade agora é hierárquica: primeiro mostra os Estados onde o escritório tem processos — mas se todos os processos filtrados estiverem no mesmo Estado, esse nível nem aparece, já indo direto pras Cidades (não faz sentido mostrar "100% no Rio de Janeiro, 0% nos demais"). Clicar num Estado mostra as Cidades dentro dele; clicar numa Cidade mostra as Varas onde os processos estão distribuídos ali (ex: "3º Juizado Especial Cível", "4ª Vara Cível", "1ª Vara de Família"...). O mesmo princípio de pular o nível quando só existe uma opção vale pra Cidade também — se um Estado só tiver processos numa única cidade, pula direto pra Varas.
🔴 Como construir
Cada processo tem natureza, estado, cidade e vara (a comarca/vara cadastrada na página do processo). Natureza é um GROUP BY simples, igual antes. Localidade agora é três níveis com auto-skip: 1) agrupe o subconjunto filtrado por estado — se COUNT(DISTINCT estado) === 1, pule automaticamente pra dentro desse estado sem renderizar a lista de estados; 2) dentro do estado (selecionado ou pulado), agrupe por cidade — mesma lógica de skip se só houver uma cidade; 3) dentro da cidade, agrupe por vara e mostre a lista final (essa não tem skip, sempre mostra, já que é o nível mais específico). Mantenha um breadcrumb (Estado / Cidade) clicável pra voltar — só mostre um segmento do breadcrumb como clicável se aquele nível tinha mais de uma opção (senão não faz sentido "voltar" pra uma lista de 1 item só).

Navegação (passo a passo, exemplo com "Direito Imobiliário"): 1) Ao clicar na barra/linha "Direito Imobiliário", faça uma query SELECT * FROM processos WHERE natureza = 'imobiliario' (combinada com os filtros ativos) e abra, logo abaixo, uma seção listando todos os processos retornados (mesmo componente de lista usado nos painéis de Movimentação/Prazos). 2) Cada processo dessa lista precisa ser individualmente clicável. 3) Ao clicar num processo específico da lista, redirecione o usuário direto para o módulo Processo, já carregando a página daquele processo (rota tipo /processos/:id) — não para uma lista geral, e sim para o processo exato que ele clicou. Esse mesmo padrão de 3 passos se repete em Vara (nível final de Localidade), status, patrocínio, movimentação, paralisados, prazos, intimações.

🟢 O que é
"Status" mostra em que fase cada processo está (aguardando decisão, em recurso, sendo executado, ou parado/suspenso). "Patrocínio" mostra em quantos processos o escritório representa o autor (quem processou), o réu (quem foi processado), ou um terceiro interessado — ajuda a entender o perfil da carteira de clientes. Também clicável, do mesmo jeito que natureza e localidade, e reage aos mesmos filtros de Escopo/Cliente/Equipe/Usuário do topo da aba.
🔴 Como construir
Status é o mesmo campo definido no módulo Processo (paralisado, suspenso, fase de conhecimento, fase recursal, execução, arquivado) — mesmo GROUP BY, sobre o mesmo subconjunto filtrado. Patrocínio vem do módulo Partes: para cada processo, verifique se o cliente cadastrado do escritório está marcado como Autor, Réu ou Terceiro Interessado (usando o mesmo campo "é cliente cadastrado" que já implementamos nas Partes) e conte por essa categoria.

Navegação: mesmo padrão de 3 passos do card de natureza/localidade acima — clicar na categoria lista os processos filtrados, clicar num processo da lista abre ele direto no módulo Processo.

🟢 O que é
"Tempo de vida médio" mostra há quanto tempo, em média, os processos ativos estão tramitando desde que começaram — processos muito antigos podem indicar algo travado. "Tempo médio entre andamentos" mostra a velocidade com que os processos costumam se mexer. "Julgados procedentes/parcialmente/improcedentes" é o histórico de vitórias, vitórias parciais e derrotas do escritório em processos já sentenciados — um indicador de desempenho.
🔴 Como construir
Tempo de vida médio: para cada processo ativo, calcule hoje - data_peticao_inicial (data do andamento tipo "Petição Inicial") e tire a média. Tempo médio entre andamentos: para cada processo, calcule a diferença de dias entre andamentos consecutivos (ordenados por data) e tire a média geral. Resultados: crie um campo resultado_sentenca no processo (nulo até ser julgado; "procedente"/"parcialmente_procedente"/"improcedente" quando julgado a favor ou contra) — preenchido manualmente pelo advogado ou identificado pela IA a partir do andamento de sentença, igual discutimos no card de Honorários Advocatícios do módulo Financeiro.
Disponível para o mestre e para quem tiver a Permissão de Gerir ligada. Mostra todos os usuários do escritório e, ao clicar em cada um, sua atividade no sistema no dia.
🟢 O que é
É a área que o dono do escritório (ou quem ele autorizar) usa pra acompanhar o trabalho de cada pessoa da equipe. A lista mostra quantas ações cada um fez hoje; ao clicar num usuário (ex: ana.gabriela), aparece a atividade dela do dia — o que exatamente ela andou fazendo no sistema. É um painel de gestão de equipe, não uma ferramenta de trabalho do dia a dia do advogado. Não é mais exclusivo do mestre: aparece pra todo mundo que tem a Permissão "Gerir" ligada em Configurações — é justamente aqui que essa pessoa vai exercer a gerência dos usuários do sistema. Os botões "Ir para Habilitações" e "Ir para Permissões" (dentro da atividade de cada usuário) levam direto pra aba Individual de Configurações — não pra aba do papel que esse usuário exerce (ex: Administrador). A diferença importa: mexer aqui altera só essa pessoa; mexer na aba do papel afetaria todo mundo que tem aquele papel.
🔴 Como construir
Essa tela só renderiza se usuario.is_mestre === true OU permissoes_papel.gerir.habilitado === true pro usuário logado — a mesma Permissão "Gerir" que já controla o acesso à área de gerência em outros lugares do sistema (Tarefas → "Tarefas de outros usuários"/"Delegadas por mim" seguem o mesmo princípio). Toda ação relevante do sistema (login, abrir processo, criar andamento, confirmar pagamento, editar parte, etc.) precisa gravar um registro numa tabela de log/auditoria (ex: logs_atividade) com: usuário, tipo de ação, descrição, timestamp, e opcionalmente o registro afetado (FK genérica ou um campo JSON com o contexto). A lista de usuários mostra COUNT(*) de logs por usuário no dia; ao clicar num usuário, busque WHERE usuario_id = X AND data = hoje ordenado por timestamp. Essa mesma tabela também serve de base pra auditoria de segurança no futuro (quem editou o quê e quando).

Navegação: clicar num usuário da lista não muda de módulo — abre, dentro do próprio Painel do gestor, a página de atividade daquele usuário (troca de "lista" para "detalhe", como já está no protótipo). Os botões "Ir para Habilitações" e "Ir para Permissões" dentro dessa página de detalhe levam para fora, para o módulo Configurações — especificamente pra aba Individual daquele usuário (/configuracoes/habilitacoes?tab=individual&usuario=X), nunca pra aba do papel dele. Isso evita o erro de alguém achar que está ajustando só uma pessoa e sem querer alterar a regra geral de todo o papel Administrador (ou Ilimitado, ou Financeiro).
🟢 Atalhos na página de detalhe do usuário
Além de ir pra Habilitações/Permissões (aba Individual), a página de detalhe de cada usuário tem mais quatro atalhos: "Grupos" leva pra gerência de Equipes já mostrando quais equipes esse usuário faz parte, com a possibilidade de adicionar ou remover ele de alguma equipe ali mesmo. "Habilitar em processos" abre, ali mesmo, a lista de todos os processos em que aquele usuário já está habilitado (e permite marcar mais) — é a mesma funcionalidade que já existe em Configurações, só que trazida como atalho pra não precisar sair do Painel do gestor pra fazer esse ajuste pontual. "Ir para Tarefas" e "Ir para Agenda" levam direto pra esses módulos já filtrados pelas tarefas/agenda daquele usuário específico, útil quando o gestor quer entender rapidamente a carga de trabalho de alguém.
🔴 Como construir

"Habilitar em processos" reaproveita exatamente o mesmo componente já construído em Configurações → Detalhe do usuário (filtro por Cliente/Matéria/Data/Busca sobre a lista completa de processos, com checklist que persiste a seleção independente do filtro, salvando em usuario_processos) — não é uma funcionalidade nova, é o mesmo componente renderizado aqui como atalho, pra evitar duplicar lógica. "Ir para Tarefas" e "Ir para Agenda" são navegação simples: redirecionam pra /tarefas?responsavel=usuario_id e /agenda?usuario=usuario_id respectivamente, já com o filtro de usuário aplicado na URL.
