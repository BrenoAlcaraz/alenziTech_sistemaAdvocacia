🟢 Como as Permissões/Habilitações controlam este módulo
O módulo Tarefas segue a mesma lógica geral configurada em Configurações → Permissões e Habilitações. A Permissão do papel do usuário (Administrador/Ilimitado/Financeiro) define "Somente os seus" ou "Todos": com "somente os seus", a lista principal só mostra as tarefas atribuídas a ele mesmo; com "todos", ele vê as tarefas de qualquer usuário do escritório. Já a Habilitação "Adicionar para todos" (dentro de Tarefas, em Habilitações) é o que decide se, ao criar uma tarefa nova, ele pode atribuir pra outras pessoas ou só pra si mesmo — se estiver desligada, o campo "Atribuir a" some ou fica travado só nele mesmo.
🔴 Como construir
Consulte permissoes_papel.tarefas.sub_opcao pro usuário logado: se 'somente_seus', filtre a query da lista principal com WHERE responsavel_id = usuario.id; se 'todos', sem filtro. Consulte também habilitacoes_papel.tarefas.adicionar_para_todos: se false, no formulário "Nova tarefa" o campo "Atribuir a" deve vir travado só no próprio usuário (nem mostrar a caixa de múltipla seleção); se true, mostra a caixa normal com todos os usuários do escritório. Como sempre, replique as duas checagens no backend — a rota de criar/listar tarefas precisa aplicar esses mesmos filtros, nunca confiar só no frontend escondendo o campo.
Voltar
É possível criar a tarefa para você mesmo, para outro usuário, ou atribuir a várias pessoas ao mesmo tempo — basta marcar cada uma na lista, ou usar o atalho "Selecionar todos".
🟢 O que é
É como o advogado (ou o mestre) anota uma pendência a ser feita — juntar um documento, ligar pro cliente, protocolar uma peça — e opcionalmente já atribui pra outra pessoa do escritório fazer. Prioridade e prazo ajudam a organizar o que é mais urgente. O campo "Atribuir a" só aparece assim, liberado pra escolher qualquer usuário, se o usuário logado tiver a habilitação "Adicionar para todos" ligada — do contrário, ele só consegue criar tarefa pra si mesmo.
🔴 Como construir
Ao renderizar este formulário, cheque habilitacoes_papel.tarefas.adicionar_para_todos do usuário logado: se false, troque a caixa multi-select por um campo fixo (só o próprio usuário, sem select). Ao salvar, para cada usuário selecionado em "Atribuir a", crie uma linha em tarefas (não uma tarefa com múltiplos responsáveis — uma linha por pessoa, com responsavel_id, criado_por: usuario_logado.id, data_criacao: hoje). No backend, mesmo que o frontend esconda o campo, a rota de criação deve recusar (403) se responsavel_id !== usuario_logado.id e a habilitação estiver desligada.

🟢 Agenda e recorrência
Marcar "Também adicionar como compromisso na Agenda" cria automaticamente um compromisso do tipo Prazo no calendário, na mesma data do prazo da tarefa — assim o advogado não precisa lançar a mesma data duas vezes, numa lista de tarefas e também no calendário. Já a Recorrência serve pra obrigações que se repetem sempre — um relatório semanal, o pagamento mensal de uma guia, uma reunião periódica — em vez de criar a tarefa manualmente toda vez, o sistema já gera as próximas ocorrências sozinho, cada uma pendente até ser concluída na sua vez.
🔴 Como construir
"Adicionar à Agenda": ao salvar a tarefa, se o checkbox estiver marcado, crie também um evento_agenda (tipo: 'prazo', título = título da tarefa, data = prazo da tarefa) vinculado por tarefa_id — assim, se a tarefa for editada ou excluída, o compromisso correspondente pode ser sincronizado ou removido junto. "Recorrência": gere um recorrencia_id compartilhado, e crie de uma vez as N ocorrências pedidas (não uma por vez via cron) — cada uma com prazo avançando pela frequência escolhida (semanal = +7 dias, mensal = +1 mês, personalizada = +X dias) a partir da primeira, e todas nascendo concluida: false. Cada ocorrência é uma tarefa independente na lista (pode ser concluída ou atrasar isoladamente), só compartilham o recorrencia_id pra referência — não é uma tarefa "mestre" com sub-itens.

🟢 O que é
A lista principal mostra as tarefas do usuário, com filtros por status: Pendentes (ainda não feitas), Concluídas (já marcadas como feitas), Atrasadas (o prazo já passou e não foi concluída). Marcar o checkbox de uma tarefa é o jeito mais rápido de dar baixa nela. Quando a Permissão do usuário em Tarefas estiver em "Todos", aparece um segundo filtro — "Minhas tarefas" / "Todas do escritório" — pra ele alternar entre ver só as próprias ou a lista completa de todo mundo. Se a permissão dele for "Somente os seus", esse segundo filtro nem aparece — ele só tem acesso às próprias tarefas mesmo.
🔴 Como construir
Status não é um campo salvo separadamente — é derivado: concluida: bool é o único campo persistido; "Pendente" = !concluida && (sem prazo OU prazo >= hoje); "Atrasada" = !concluida && prazo < hoje; "Concluída" = concluida === true. O filtro de escopo (Minhas/Todas) só renderiza se permissoes_papel.tarefas.sub_opcao === 'todos' pro usuário logado; a query muda de WHERE responsavel_id = usuario.id (Minhas) pra sem filtro de responsável (Todas do escritório) conforme o que ele escolher — mas o próprio filtro só pode existir se a permissão permitir "todos" pra começo de conversa.
🟢 Aviso quando a tarefa é concluída
Quando alguém marca como feita uma tarefa que outra pessoa atribuiu a ela, quem pediu recebe um aviso — o sino no topo da tela mostra a notificação, com o nome de quem concluiu e o título da tarefa. Assim, quem delegou não precisa ficar checando a lista do outro pra saber se a tarefa foi feita. Se a tarefa foi criada pela IA (ou pela própria pessoa, pra si mesma), não faz sentido gerar aviso — só dispara quando é de fato um pedido de uma pessoa pra outra.
🔴 Como construir
Ao marcar concluida: true, se criado_por !== responsavel_id e criado_por for um usuário real (não a IA), crie um registro em notificacoes (tarefa_id, concluido_por, destinatario: criado_por, data). O sino consulta COUNT() dessas notificações não lidas pro usuário logado pra mostrar o número no badge, e a lista suspensa mostra as mais recentes. Marque como lida quando o usuário abrir o dropdown (ou clicar na notificação específica), pra não ficar acumulando pra sempre.
🟢 Tarefas concluídas somem depois de 7 dias
Uma tarefa concluída não precisa ficar marcada pra sempre na lista — depois de 7 dias, ela é removida automaticamente de todas as visualizações (lista principal, aba do mestre, etc.), mantendo a tela limpa e focada no que ainda está em aberto ou foi concluído recentemente. Não é uma exclusão física imediata de dados históricos — é só uma questão de não poluir a visão do dia a dia.
🔴 Como construir
Salve data_conclusao no momento em que concluida vira true (limpe o campo se for desmarcada de volta). Toda query que lista tarefas deve incluir AND (concluida = false OR data_conclusao >= hoje - 7 dias), escondendo da tela qualquer tarefa concluída há mais de uma semana. Pra exclusão física real dos dados (não só escondida da tela), rode um job diário que deleta (ou arquiva, se quiser manter histórico/auditoria) as tarefas com concluida = true AND data_conclusao < hoje - 7 dias — mas a regra de esconder da tela deve valer independente do job já ter rodado ou não, calculada sempre pela data, nunca por um campo booleano tipo "expirada".

🟢 O que é
Notifica todas as tarefas que entraram na lista do usuário nas últimas 24 horas, não importa quem criou — pode ser ele mesmo, um colega, ou até a IA (identificando algo que precisa ser feito a partir de um andamento do processo, por exemplo). É a forma rápida de ver "o que apareceu de novo pra mim" sem precisar rolar a lista inteira.
🔴 Como construir
Filtre tarefas WHERE responsavel_id = usuario.id AND data_criacao >= now() - 24h, sem filtrar por criado_por — o objetivo é pegar qualquer origem. Ordene por data_criacao DESC pra mostrar as mais recentes primeiro. O contador no badge da aba é só o COUNT() desse mesmo filtro.
🟢 O que é
Diferente da aba anterior (que pega qualquer origem, inclusive você mesmo ou a IA), esta é mais específica: só mostra tarefas que outra pessoa atribuiu a você — qualquer colega do escritório, não só quem está acima na hierarquia. Isso porque, na prática, um advogado com papel Ilimitado pode perfeitamente passar uma tarefa pra outro colega do mesmo papel, não só o mestre ou um superior repassando trabalho pra baixo.
🔴 Como construir
Filtre tarefas WHERE responsavel_id = usuario.id AND criado_por != usuario.id — qualquer criador diferente do próprio responsável entra aqui, sem checar hierarquia nem cargo. Isso é mais simples do que a versão anterior (que dependia de um campo superior_id): não precisa de nenhuma lógica de hierarquia pra essa aba funcionar, só comparar quem criou com quem é o responsável.
🟢 O que é
Mostra todas as tarefas que o próprio usuário atribuiu a outra pessoa — não só as recentes, a lista completa mesmo — pra ele acompanhar o que já foi cumprido e o que ainda está em aberto, sem precisar ficar checando a lista de cada colega um por um. É o espelho da aba "Adicionada por terceiro": lá você vê o que os outros mandaram pra você, aqui você vê o que você mandou pros outros.
🔴 Como construir
Filtre tarefas WHERE criado_por = usuario.id AND responsavel_id != usuario.id, ordenado por status (pendentes/atrasadas primeiro, concluídas depois) ou por data. Essa aba só deve renderizar se habilitacoes_papel.tarefas.adicionar_para_todos === true pro usuário logado — mesma habilitação que já controla se ele pode escolher outros no campo "Atribuir a" ao criar uma tarefa (faz sentido: só quem pode delegar tarefa tem o que acompanhar aqui).
Disponível para quem tem a habilitação de atribuir tarefas para terceiros. Veja as tarefas de qualquer usuário do escritório e adicione novas diretamente para ele.
🟢 O que é
Quem tem a habilitação de atribuir tarefa pra terceiros pode escolher um usuário do escritório e ver a lista de tarefas dele, podendo inclusive criar uma tarefa nova diretamente pra essa pessoa sem precisar que ela mesma cadastre. Útil pra quem coordena uma equipe acompanhar/delegar sem depender de cada funcionário organizar a própria lista.
🔴 Como construir
Essa aba (e o botão que leva até ela) só deve renderizar se habilitacoes_papel.tarefas.adicionar_para_todos === true pro usuário logado — a mesma habilitação da aba "Delegadas por mim" e do campo "Atribuir a" no formulário. Não é mais uma trava fixa de perfil mestre — qualquer papel com essa habilitação ligada enxerga isso. Ao selecionar um usuário no seletor, busque tarefas WHERE responsavel_id = usuario_selecionado.id. O botão "+ Nova tarefa para esta pessoa" reaproveita o mesmo formulário de criação, só que com o campo "Atribuir a" pré-preenchido e travado nesse usuário.
